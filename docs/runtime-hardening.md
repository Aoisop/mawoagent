# 运行可靠性与 Skills 发布流程

> 返回：[文档索引](README.md)

更新日期：2026-10-15。本说明对应当前实现，补充此前的在线 Skills 评测说明。

## 工具执行和权限

OpenAI 与 Anthropic 共用执行入口：校验工具参数的 JSON Schema，按当前模式检查权限，完成必要确认，再执行工具。每条写入和模式切换按顺序处理。进入计划模式后，同一批后续工具也受计划权限限制。模型响应被截断，或 OpenAI 流缺少结束标识时，该响应内的工具不执行。

MCP 的每次确认展示具体参数，不复用之前同名工具的确认。MCP 启动和工具调用分别检查权限。

Skill fork 可以借用父 Agent 已连接的 MCP 工具，但仍受子任务工具白名单和当前权限限制；子任务退出不会关闭父连接。连接由父 Agent 统一释放。

MCP 单条消息上限为 8 MiB，支持超过原来约 64 KiB 限制的工具列表和文本响应。超限或读取连接断开会明确报错，后续调用立即失败；需重新建立连接后再使用。stderr 按块消费，长行不会阻塞子进程。`isError=true` 转为明确的工具失败，结构化结果 `structuredContent` 也会保留。

用户级配置的权限规则可直接生效。项目级 deny 始终生效；项目级 allow 只有在用户输入 `/trust-project` 后生效。信任记录属于用户，绑定项目绝对路径及 `.mawoagent/settings.json`、`.mcp.json` 的内容摘要。配置发生变化需要重新信任。`--yolo` 仍是显式跳过权限检查的模式。

文件规则匹配规范化的绝对路径及符号链接路径，`file.txt`、`./file.txt` 和指向同一文件的绝对路径不能绕过 deny。搜索与文件列表同时按具体文件过滤权限，搜索也遵守 `read_file` 的 deny。搜索统一使用 Python 正则语义。

`read_file` 支持从 1 开始的 `offset` 和 `limit`，默认最多 1000 行；正文与行号共用 24 KiB 预算，另附简短分页提示，整段结果保持在 30 KiB 以下。局部读取后优先用 `edit_file` 修改目标片段，避免整份替换未读内容。超长单行仅展示开头，需要通过经授权的 Shell 定向提取字符范围。读取内容与同一次打开的文件版本绑定；写入前再次检查设备、inode、大小及纳秒修改时间，暂存完整内容后原子替换。此检查不等同于与外部编辑器共享的事务锁。

## 自动学习、评测、发布、回退

自动学习把新增或合并建议保存在 `.mawoagent/skill-evolution/candidates/`。候选包含完整指令、目标 Skill 和提案时活跃文件的摘要。允许维护操作的权限模式下才会保存候选。

```text
/skill-candidates
/skill-eval
/skill-apply <candidate-id>
/skill-rollback <skill-name>
```

`/skill-candidates` 展示候选内容。已有 Skill 的待合并候选进入开发和测试回放，使用将发布的完整正文评测。`/skill-apply` 默认要求候选与通过评测的冠军快照一致，并要求活跃文件未发生变化。候选在用户确认期间被修改也会拒绝发布。发布仍须通过当前写权限检查。

候选创建时固化日期、最终正文及写入参数摘要，评测和跨日发布使用同一份正文。旧候选首次读取时原子迁移为固定快照；迁移前的评测结果不能自动授权新快照，需要重新评测或明确人工审核。

新 Skill 尚无活跃基线或使用统计时，通常无法完成自动晋级。操作者可以在审阅内容后明确使用 `/skill-apply <id> --manual-review` 发布。此选项表示人工审核路径，不能把它描述为已经通过回放评测。

修改已有 Skill 前保存完整旧版本。回退也保存当前版本，因此回退操作可再次撤销。自动合并必须提供完整的新正文，旧指令保留在版本快照里，避免矛盾要求同时进入活跃正文。词项检索分数用于提供参考，不会仅因超过某个分数就强制合并。

## 验收条件

`requirements` 中的字符串默认是必须通过的语义要求。可以明确配置可选质量项：

```json
{
  "requirements": [
    "说明写入中断导致配置损坏的风险",
    {"text": "表达尽量简洁", "required": false}
  ],
  "checks": [
    {
      "mode": "json_schema",
      "schema": {
        "type": "object",
        "required": ["risks"],
        "properties": {
          "risks": {"type": "array", "items": {"type": "string"}}
        }
      }
    }
  ]
}
```

必须通过的语义要求有任一失败，候选无法胜出或晋级，其他得分无法抵消。可选质量项继续参与分数。格式、字段、类型可以交给程序校验；语义仍由模型判分。外部 JSON Schema 引用不联网获取。

配置 `MAWOAGENT_SKILL_JUDGE_MODEL` 可在相同 API 服务上使用另一模型判分。生成和裁判调用共享调用上限，缓存分别保存。报告标明裁判是否单独配置。严格格式校验和更换裁判都不能保证事实判断正确，需要人工抽检和真实任务数据。

## 会话、后台任务与数据

会话保存技能学习上下文、待反馈窗口和稳定的对话分组标识。恢复时保留这些信息；旧会话尽可能从有效聊天记录重建上下文。保存中的计划模式会在默认启动模式下恢复；显式选择其他启动权限模式时采用本次配置。

主 Agent 每批工具开始前、每项工具执行前后保存检查点。保存失败时阻止尚未开始的工具执行。进程异常退出后，恢复逻辑补全协议消息：已完成的工具使用保存的结果，尚未开始的工具标记为未执行，开始但未保存结果的工具标记为结果未知。Runtime 不自动重放这些操作；结果未知时应先核对文件或外部服务的实际状态。这不是跨本机文件、Shell 和外部服务的事务，也不能保证副作用恰好执行一次。子 Agent 的中断由父任务的检查点标记为结果未知。

超过 30 KiB 的工具结果先独立、原子落盘，再将受限预览和文件引用写入完成检查点。后续会话保存不重复嵌入原件；恢复也使用预览，完整结果按需分页读取。旧会话的大结果恢复采用内容摘要命名，重复恢复复用完整且校验通过的原件。执行前后的持久化边界继续保留。

用户对上一轮的反馈先进入随会话保存的待提交列表，再提交给持久化后台队列，不依赖下一轮回答是否成功。请求错误、取消、截断或队列写入失败时，反馈仍可恢复。计划模式或禁用学习时暂缓提交。只有正常结束的回答会建立新的学习窗口。

后台学习默认最多两项同时运行，内存中最多接纳十六项任务。队列满、退出取消或执行失败时，任务记录保留在 `pending-jobs/`。后续对话恢复可处理的任务，最多尝试三次；不恢复其他仍在运行的进程所拥有的任务。计划模式和禁用学习时不重试。Windows 上异常终止且仍记录进程所有权的任务暂需人工核对记录；正常退出会释放所有权。

来源日志使用 SQLite 增量索引，每个 Skill 的近期记录数量受来源池上限约束；原始日志保留用于审计。文件轮换或截短时重建索引。评测冠军更新会检查比较期间是否出现新冠军，避免旧比较结果覆盖新结果。

`/cleanup-state [days]` 默认只展示超过保留期的工具结果和评测运行目录，默认三十天。显式加 `--apply` 才删除，并检查写权限。当前冠军对应的运行目录保留。原始来源日志、会话、版本快照不在此删除范围内。

## 上下文、召回和流式重试

两种协议在每次主模型请求前共用上下文检查，不再依赖是否调用工具。估算同时考虑历史消息、系统提示、工具定义以及本轮新增内容，并参考上一轮实际输入用量。估算超过阈值时尝试折叠；估算不是模型专用 tokenizer，不能保证任意模型、超长单条输入都不超限。折叠失败继续保留原历史。

工具触发压缩或清空上下文后，只为新历史中仍存在的工具调用补齐结果，避免向 OpenAI 请求追加没有对应调用的 `tool` 消息。

Memory 召回在首次主模型请求前最多等待两秒，避免直接回答跳过召回。超时取消召回任务并继续回答；调用方取消也会传递到召回任务。可通过 `Agent(memory_recall_timeout=...)` 调整时限；召回内容遵守会话记忆字节预算。

流式请求按每次尝试隔离输出。失败或取消的尝试从正式输出和学习缓冲区移除，Web 同时恢复到该次请求开始前的显示状态。终端已经显示的文本无法撤回，会提示该段回答作废。重试成功后，学习记录只包含成功尝试的文本。

公共逻辑分别位于 `context_runtime.py`、`streaming.py` 和 `checkpoints.py`，协议相关的流解析保留在 `agent.py`。

工具结果压缩位于 `tool_results.py`，独立于模型、磁盘和 UI；Anthropic 工具调用建立一次索引，避免每个结果都扫描全部历史。保留两种协议原有的结果保留策略。普通子 Agent 和 Skill fork 共用初始化、权限与预算继承、关闭和用量结算流程。

`config.py` 集中 CLI、Web、评测入口的环境变量与模型配置，Web 不再依赖 CLI 模块。工具 Schema 位于 `tool_schemas.py`，`agents.tools` 继续提供原有导入接口。

Memory 召回扫描只读取受限文件头（最多 30 行、16 KiB），按修改时间选择最多 200 条摘要。选中文件的正文直接按 4096 字节预算读取，UTF-8 尾部不完整字符会被安全截去。单个文件删除或解码失败不会导致其他已选记忆全部丢失。

## 安装与检查

建议 Python 3.11 或 3.12，安装经过当前环境验证的依赖版本：

```bash
python -m pip install -r requirements.lock
python -m unittest discover -s tests -q
node --check web/app.js
node --test web/tests/*.test.mjs
```

CI 配置了 Linux、macOS、Windows 的 Python 3.11/3.12 检查，以及 Node.js 22 的前端回归检查。本地离线测试覆盖实际 SDK 的模拟流解析、权限切换、完整输出保存、候选发布与回退、语义门禁、后台恢复和持久化。

`tests/test_reliability_boundaries.py` 增加断流重试、纯聊天压缩、首次回答召回、反馈恢复、大 MCP 响应等故障注入测试。端到端恢复案例会在临时目录中实际写入文件，随后通过 `os._exit` 强制结束工作进程，核对磁盘产物、检查点和恢复后的协议消息。模型响应在测试中固定，不调用付费模型；这些测试验证 Runtime 行为，真实模型质量、检索阈值与泛化效果仍需要独立任务和重复实验校准。

已知模型使用内置容量表。未知模型默认按 32000 token 处理，可以通过 `--context-window` 或 `MAWOAGENT_CONTEXT_WINDOW` 指定实际容量。输入/输出价格仍需要按照使用的服务配置，尤其是在裁判采用不同模型时。
