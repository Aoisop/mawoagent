## 2.5 自主会话记忆折叠：目的与价值

### 目的

面向代码探索、调试、重构和多工具协作等长程任务，避免原始对话、工具结果和失败尝试持续堆积，导致上下文膨胀、关键信息被淹没或错误路径持续影响后续推理。

### 核心收益

- **降低上下文开销**：将冗长交互历史压缩为结构化 session state，释放上下文空间。
- **保持任务连续性**：保留整体进展、当前子目标、阻塞问题、下一步动作和工具经验，折叠后可以继续执行。
- **减少错误累积**：在重复失败或策略变化时清理噪声，让 Agent 重新审视当前状态并调整方案。
- **提升长程任务稳定性**：相比固定截断或简单摘要，三层 memory schema 能更稳定地保留任务事实、工作状态和工具使用经验。

### 简历表述

> 设计自主会话记忆折叠机制，使 Agent 能在长程任务中主动或按上下文阈值压缩历史交互，保留任务进展、当前工作状态和工具经验，并基于折叠后的结构化 session state 继续推理和执行。

## 5. 30 秒面试讲法

mawoagent 是我用 Python 实现的一个自进化命令行 Coding Agent。它的核心是自研 Agentic Harness，不是简单套 API，而是统一编排模型推理、工具调用、权限控制、自主会话记忆折叠、Skills、MCP 和子 Agent。最大亮点有两个：一是会话记忆可以在长对话中主动折叠，把上下文压成结构化 session state，适合长程任务；二是 Skills 自进化与评测，系统会把用户下一轮反馈作为证据沉淀成 `SKILL.md`，再用真实 replay、规则编译、LLM judge、candidate variants 和 champion 机制评估 Skill 是否稳定可用。

## 6. 1 分钟面试讲法

这个项目主要解决两个问题：第一，怎么把大模型变成能安全执行软件工程任务的本地 Agent；第二，怎么让 Agent 在使用过程中沉淀能力。  

我实现了一个 Python Agentic Harness，负责模型调用、tool call 解析、权限检查、工具执行、结果回写、会话记忆折叠和会话保存。上层支持文件读写、代码搜索、Shell、Plan Mode、OpenAI / Anthropic 双协议、Memory、Skills、MCP 和子 Agent。会话变长、工具反复失败或需要调整策略时，模型可以主动调用 `compact_context`，系统也提供上下文阈值兜底；折叠后保留任务进度、当前目标和工具经验，继续完成长程任务。

项目最核心的亮点是自进化 Skills 和在线评测。每轮回复结束后系统会保存 pending window，下一轮用户反馈会被合并为证据，再由 Extractor 抽取可复用候选，Maintainer 判断 add / merge / discard，最后写入或演化 `SKILL.md`。评测阶段会从 provenance 构造 replay，编译规则，调用 LLM judge，结合 usage stats 给出状态；如果历史回复失败，还会生成 candidate variants 重新试跑并记录 champion 产物。整个过程有权限控制、provenance 记录、版本快照和评测产物，不是无约束让模型随便改 prompt。

## 7. 2 分钟深度讲法

mawoagent 的底层是一个自研 Agentic Harness。用户输入进入 `Agent.chat()` 后，系统会初始化 MCP、检索相关 Skills、预取 Memory，然后根据配置选择 OpenAI-compatible 或 Anthropic-compatible 模型接口。模型如果返回 tool call，Harness 会先进入统一的权限检查逻辑，再分发到内置工具、Skill、MCP 工具或子 Agent，执行结果会作为 tool result 回写给模型，形成推理、行动、观察、继续推理的闭环。

在这个闭环里，我重点补了自主会话记忆折叠：当上下文变长时，模型可以主动调用 `compact_context`，系统也会在达到阈值时自动折叠，把原始对话压缩成结构化 session state 后继续执行。这样做的价值是，长任务不会因为窗口膨胀而中断，模型还能保留任务进度、工具经验和下一步动作。

我在这个闭环上做了几个扩展：第一是 Plan Mode，复杂任务先只读分析和写计划，审批后再执行；第二是 Memory 和 Skills 分层，Memory 记录事实和偏好，Skills 记录可复用方法；第三是 MCP Client，通过 stdio JSON-RPC 动态接入外部工具；第四是子 Agent，用隔离上下文处理探索、规划和局部任务。

最重要的是 Skills 自进化和在线评测。系统会把用户任务、助手回复和下一轮用户反馈组成 pending window，用 Extractor 抽取未来可复用的规则，再由 Maintainer 基于已有 Skills 做相似检索和 add / merge / discard 判断。新增或演化时会写 `SKILL.md`，记录 usage、provenance、版本快照和 retrieved / relevant / used 统计。随后 `/skill-eval` 会基于在线日志构造 replay 样本池，从 Skill 文本编译规则，使用程序检查和 LLM judge 评估历史回复，并根据失败规则生成 candidate variants 重新试跑；只有证据足够且候选优于当前版本时，才记录 champion 产物，保证自进化能力可控、可追溯、可比较。

## 8. STAR 表达

### S：背景

普通大模型工具完成任务后，经验只停留在当前上下文中；用户下次提出同类任务时仍需要重复说明偏好、格式和工作流。同时，让模型直接操作文件和 Shell 存在安全风险。

### T：目标

实现一个本地 Harness Agent，不仅能安全执行软件工程任务，还能从用户反馈中沉淀可复用能力，逐步形成项目级和用户级 Skills。

### A：行动

- 设计 Agentic Harness，统一处理模型请求、工具调用、权限检查、结果回写和会话保存。
- 设计自主会话记忆折叠机制，在上下文膨胀、重复失败或策略切换时压缩历史交互，保留关键任务状态并支持折叠后继续执行。
- 实现文件读写、精确编辑、代码搜索、Shell、Plan Mode、MCP、子 Agent 和 Skills 调用。
- 设计 Skills 自进化链路，使用 pending window 合并下一轮用户反馈，通过 Extractor 抽取候选，再由 Maintainer 判断 add / merge / discard。
- 实现 `SKILL.md` 落盘、版本 bump、演化前快照、provenance 记录、usage stats 和 stale Skill 归档。
- 实现在线 Skills 评测链路，构造 replay pool，编译 programmatic / LLM judge 规则，评估历史回复，生成 candidate variants 试跑，并通过 champion registry 记录健康版本。
- 设计会话 Memory + 长期 Memory + Skills 分层，分别承载当前任务状态、项目事实和可复用任务方法，避免不同类型的信息相互污染。

### R：结果

项目形成了一个可运行的自进化 Harness Agent：既能完成代码阅读、文件编辑、测试执行、架构分析等 Coding Agent 任务，又能通过自主会话记忆折叠稳定推进长程任务，将稳定用户反馈沉淀为可复用 Skills，并通过 replay 评测、LLM judge、candidate 试跑和 champion 产物回溯来源、版本、质量和使用效果。
