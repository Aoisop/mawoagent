# 项目优化检查与本轮修改总结

日期：2026-10-12。

本文件只总结本轮“检查项目并优化”的新增修改。之前完成的 U1/A1/U2 目标绑定、会话分组、候选配对评测等作为现有基础，不重复列作本轮新成果。

## 一、本轮发现并修复的问题

### 1. Skill 使用率可能被错误判分污染

**问题证据：** `judge_retrieved_skill_usage()` 原来使用 `bool(raw.get("used"))` 和 `bool(raw.get("relevant"))`。Python 中 `bool("false")` 为真，模型返回字符串时会把“不相关/未使用”记成正面证据。缺失判定则当作否定，可能影响淘汰。无判分模型时，旧回退逻辑仅靠回答是否出现 Skill 名称判断使用情况。

**修改：**要求判分覆盖全部 Skill、名称唯一匹配、字段为真正布尔值，并拒绝“使用但不相关”的矛盾结果。非法结果拒绝写统计；无判分模型时不生成判定。统计写入入口再次验证，防止其他调用路径绕过。

**另一个问题：**后台使用追踪以前在协程真正执行时才读取 Agent 当前检索结果；进入新一轮后可能读到新任务的 Skill。现在在调度前复制本轮 hits，再传给后台任务。

**边界：**格式正确不等于模型语义判断正确。旧统计不会自动清洗；历史日志中若已有错判，需要另外审计，不能凭空重写。被拒绝的判分不计入这套使用率统计，不能把该统计分母当作完整检索次数。

### 2. 子代理预算结算不完整

**问题证据：**普通子代理和 Skill fork 只在成功时把返回的主模型 token 加回父代理；异常、取消、辅助调用 token 和工具轮次没有完整结算。连续创建子代理时可能重复获得本应已经消耗的预算。

**修改：**两条入口都在 finally 中从子代理计数器结算主模型 token、辅助模型 token 和已用轮次。成功、异常和取消都执行；取消继续向上传播。

**补充：**OpenAI 与 Anthropic 路径在进入对话和实际主模型请求前检查现有预算，预算已经耗尽时不再发起下一次主模型请求。

**边界：**金额仍按项目现有固定单价估算，不能当真实账单。已开始的请求、SDK 重试以及未收到 usage 的失败请求不能精确结算。max_turns 仍沿用现有工具调用轮次口径，本轮没有改成所有 API 请求次数上限。

### 3. 空工具白名单和递归限制存在漏洞

**问题证据：**`if allowed_tools` 会把显式空列表当成未配置，Skill fork 因而获得默认工具集。自定义子代理的配置分支也存在相同判定；显式白名单还可能加入 agent 工具，绕过默认分支的递归限制。

**修改：**区分 None（未配置）与 []（零工具）；子代理与 Skill fork 的入口都移除 agent 工具，保留原有计划模式工具限制。

**边界：**这是工具配置约束，不等于操作系统沙箱。自定义子代理仍可能调用其他业务工具；完整递归深度治理和系统级隔离是另一项工作。

### 4. 等待用户输入会阻塞后台自进化

**问题证据：**异步 REPL 直接调用同步 input()，等待输入期间事件循环无法继续调度后台使用追踪和自进化。

**修改：**REPL 主输入改为独立守护线程读取，通过事件循环安全地回传结果，等待输入时后台协程可以继续运行。守护线程避免退出时被尚未返回的标准输入长期拖住。

**边界：**工具确认和计划审批仍使用原有输入方式；本轮只处理主 REPL 等待输入。后台输出可能与输入提示交错，终端交互体验仍可继续改进。

### 5. 评测命令缺少读取一致性与错误隔离

**问题证据：**触发 `/skill-eval` 时后台来源写入可能尚未完成；审核 JSON 损坏、读写失败会从命令分支直接抛出，退出交互循环。

**修改：**先等待已调度后台任务完成，再读取评测数据；对 ValueError、OSError 显示错误并返回 REPL，保留原文件，不静默重置人工审核。

**边界：**等待后台任务没有新增整体超时。这里只处理常见数据/文件异常，不隐藏任意程序错误；跨进程同时改写仍需要文件锁或事务支持。

## 二、验证结果

新增 `tests/test_runtime_reliability.py`，增加 8 项测试，覆盖：

- 字符串 false、缺项、错名、矛盾使用判定，以及无模型时不猜使用情况。
- 非法判分批次不产生统计文件。
- 普通子代理与 Skill fork 在成功、异常、取消三种路径均结算用量。
- 两种模型后端在零轮次或零费用预算时不调用 API。
- 等待用户输入时后台任务继续运行；EOF 正确返回。
- 损坏评测数据只报错，不中断后续 REPL 命令；读取前完成后台任务。
- 使用追踪使用调度时捕获的 hits。
- 自定义子代理的空白名单及 agent 工具过滤。

执行命令：

```bash
python -m unittest discover -s tests -q
```

本轮最终结果：**44 项测试全部通过**，`git diff --check` 通过。没有调用付费模型；这些是程序行为测试，不是模型能力通过率，也不证明项目不存在其他缺陷。
