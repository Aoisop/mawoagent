# mawoagent 架构设计

## 1. 总体定位

mawoagent 的核心是 Harness。

模型负责推理和提出工具调用意图，Runtime 负责真正的执行边界、上下文管理、会话保存、Skills 自进化和外部扩展。

普通聊天工具通常是：

```text
用户输入 -> 调模型 -> 打印回复
```

mawoagent 更接近：

```text
用户输入
  -> CLI / REPL
  -> Agentic Harness
  -> Prompt / Skills / Memory / MCP 初始化
  -> 模型推理
  -> tool call
  -> 权限检查
  -> 工具执行
  -> tool result 回写
  -> 多轮循环
  -> session 保存
  -> Skills usage tracking
  -> online skill evolution
```

它的架构重点是把模型、工具、记忆、技能和外部能力统一编排到一个可控 runtime 里。

## 2. 架构总览

从层次上看，系统可以分成六层：

| 层级 | 主要文件 | 职责 |
|------|----------|------|
| 入口层 | `agents/main.py`、`agents/ui.py` | 参数解析、REPL、one-shot、终端输出 |
| Harness 层 | `agents/agent.py` | Agent Loop、协议适配、工具调度、上下文压缩、session 保存 |
| 能力层 | `agents/tools.py`、`agents/skills.py`、`agents/memory.py`、`agents/mcp_client.py`、`agents/subagent.py` | 工具、Skills、Memory、MCP、子 Agent |
| Prompt 层 | `agents/prompt.py` | 动态构建 system prompt |
| 演化层 | `agents/online_skill_evolution.py`、`agents/skill_evolution.py`、`agents/online_skill_eval.py` | Skills 抽取、演化、审计、评测 |
| 持久化层 | `.mawoagent/`、`~/.mawoagent/`、`~/.mawoagent/`、`~/.mawoagent/` | Skills、Memory、Session、审计和大结果持久化 |

这几个层级的边界比较清楚：

- `main.py` 只管入口。
- `agent.py` 只管运行时调度。
- `tools.py` 只管工具和权限。
- `skills.py` / `skill_evolution.py` 只管能力沉淀。
- `memory.py` 只管长期事实。
- `mcp_client.py` 只管外部工具接入。
- `subagent.py` 只管隔离上下文任务。

## 3. 一次请求的主链路

主链路从 `agents/main.py` 进入，最终落到 `Agent.chat()`。

```text
用户输入
  -> run_repl() / run_one_shot()
  -> Agent.chat(user_message)
  -> 首次 chat 初始化 MCP
  -> 检索 Skills 并注入用户消息
  -> 异步预取 Memory
  -> 选择 _chat_openai() 或 _chat_anthropic()
  -> 模型返回文本或工具调用
  -> _execute_tool_call()
  -> 权限检查与工具执行
  -> tool result 回写模型
  -> 模型继续推理或结束
  -> 后台执行 Skill usage tracking / online evolution
  -> 保存新的 pending window
  -> 自动保存 session
```

这条链路里最重要的三件事是：

1. 模型不直接操作环境。
2. 工具执行前有权限边界。
3. 任务结束后才进入能力沉淀链路。

## 4. 入口层

入口层主要在 `agents/main.py`。

它负责：

- 解析 CLI 参数。
- 加载 `.env`。
- 判断模型协议。
- 创建 `Agent`。
- 启动 REPL 或一次性任务。
- 处理 `/skills`、`/memory`、`/compact`、`/plan`、`/skill-*` 等命令。

关键函数：

| 函数 | 作用 |
|------|------|
| `parse_args()` | 解析模型、权限、计划模式、resume 等参数 |
| `_load_env_file()` | 加载当前目录或父目录的 `.env` |
| `_resolve_api_config()` | 判断 OpenAI-compatible 还是 Anthropic-compatible |
| `run_repl()` | 交互式主循环 |
| `run_one_shot()` | 一次性执行 |
| `main()` | 程序总入口 |

入口层不关心工具细节，也不关心 Skills 如何演化。它只负责把配置和输入送进 Runtime。

## 5. Harness 层

Harness 层集中在 `agents/agent.py`，这是最核心的模块。

`Agent` 维护的主要状态有：

| 状态 | 含义 |
|------|------|
| `permission_mode` | 当前权限模式 |
| `model` | 当前模型名 |
| `use_openai` | 是否走 OpenAI-compatible 路径 |
| `tools` | 当前可用工具列表 |
| `_anthropic_messages` / `_openai_messages` | 双协议消息历史 |
| `_mcp_manager` | MCP 管理器 |
| `_last_retrieved_skill_reference` | 本轮检索到的 Skill 参考 |
| `_pending_skill_extraction_window` | 等待下一轮反馈的沉淀窗口 |
| `_background_skill_tasks` | 后台 skill usage / evolution 任务 |

`Agent.chat()` 是 Runtime 的主入口，它会把任务拆给内部方法：

| 方法 | 职责 |
|------|------|
| `_augment_user_message_with_skill_context()` | 检索相关 Skills 并注入消息 |
| `_chat_openai()` | OpenAI-compatible 主循环 |
| `_chat_anthropic()` | Anthropic-compatible 主循环 |
| `_execute_tool_call()` | 统一分发工具调用 |
| `_execute_skill_tool()` | 执行 Skill |
| `_execute_agent_tool()` | 启动子 Agent |
| `_run_online_skill_evolution()` | 后台在线自进化 |
| `_run_skill_usage_tracking()` | 判断 Skill 是否真的有用 |
| `_run_compression_pipeline()` | 控制长上下文和大结果 |
| `_auto_save()` | 保存 session |

## 6. 模型协议适配

mawoagent 支持两类协议：

- OpenAI-compatible
- Anthropic-compatible

协议判断在 `agents/main.py::_resolve_api_config()`。

运行时分支在 `Agent` 里：

```text
if self.use_openai:
    self._chat_openai(user_message)
else:
    self._chat_anthropic(user_message)
```

两条路径的区别主要在消息和 tool call 表达格式：

| 差异点 | OpenAI-compatible | Anthropic-compatible |
|--------|-------------------|----------------------|
| 客户端 | `openai.AsyncOpenAI` | `anthropic.AsyncAnthropic` |
| 消息容器 | `_openai_messages` | `_anthropic_messages` |
| 工具格式 | `tool_calls` | `tool_use` block |
| tool result 回写 | `tool` role message | `tool_result` block |

但它们共享同一套：

- 工具系统。
- 权限系统。
- Skills。
- Memory。
- session。
- 自进化链路。

## 7. 工具系统与权限架构

工具系统在 `agents/tools.py`。

工具定义集中在 `tool_definitions`，包括：

- `read_file`
- `write_file`
- `edit_file`
- `list_files`
- `grep_search`
- `run_shell`
- `skill`
- `compact_context`
- `skill_evolve`
- `skill_create`
- `agent`
- `tool_search`

执行流程：

```text
模型发起 tool call
  -> Agent._execute_tool_call()
  -> 特殊工具先由 Agent 层路由
  -> 普通工具进入 tools.execute_tool()
  -> check_permission()
  -> 具体工具函数执行
  -> 结果格式化 / 截断
  -> tool result 回写模型
```

权限边界包括：

- 只读工具默认允许。
- Plan Mode 下阻断普通写操作和 Shell。
- `acceptEdits` 允许编辑类操作。
- `bypassPermissions` 直接放行。
- `dontAsk` 自动拒绝需要确认的动作。
- 编辑前要先读文件，并检查 mtime。
- 默认模式下每次 Shell 调用和文件写入、编辑都需要确认；`acceptEdits` 自动批准专用文件编辑工具，Shell 仍需确认。Skill 创建和演化也需要确认。

这一层的目标不是阻止 Agent 工作，而是把风险动作显式化。

## 8. Skills 架构

Skills 是 mawoagent 的长期方法载体。

它们以目录型 `SKILL.md` 存在：

```text
<project>/.mawoagent/skills/<skill_name>/SKILL.md
~/.mawoagent/skills/<skill_name>/SKILL.md
```

Skill 保存的是“可复用方法”，比如：

- 代码审查流程。
- 文档写作风格。
- 某类任务的输出结构。
- 某个领域的操作步骤。

相关模块：

| 文件 | 职责 |
|------|------|
| `agents/skills.py` | 加载、解析、检索、执行 Skill |
| `agents/skill_evolution.py` | 创建、演化、版本快照、provenance、usage stats |
| `agents/online_skill_evolution.py` | 在线抽取候选、决策 add / merge / discard |

运行时分三段：

```text
对话前
  -> discover_skills()
  -> retrieve_relevant_skills()
  -> format_retrieved_skill_context()
  -> 注入用户消息

对话中
  -> 模型调用 skill 工具
  -> inline / fork 执行

对话后
  -> judge_retrieved_skill_usage()
  -> online_ingest()
  -> create_skill_file() 或 evolve_skill_file()
```

## 9. 自进化架构

Skills 自进化是 mawoagent 最核心的差异点之一。

它的目标不是让 Agent 随机改 prompt，而是把用户明确反馈中稳定、可复用、未来仍有价值的方法沉淀为 Skill。

链路分四步：

1. 当前轮完成任务。
2. 下一轮用户反馈到来。
3. Extractor 抽取候选 Skill。
4. Maintainer 决定 add、merge 或 discard。

落盘和审计都在 `agents/skill_evolution.py`：

| 能力 | 说明 |
|------|------|
| `create_skill_file()` | 创建新的 `SKILL.md` |
| `evolve_skill_file()` | 演化已有 Skill，并保存 history 快照 |
| `record_online_skill_provenance()` | 记录来源证据 |
| `record_skill_usage_judgments()` | 记录 retrieved / relevant / used 统计 |
| `format_skill_stats()` | 输出 Skill 使用效果 |

这种设计让自进化具备：

- 用户反馈证据。
- add / merge / discard 决策。
- 版本快照。
- provenance。
- usage stats。
- stale 归档。

## 10. Memory 架构

Memory 和 Skills 的职责不同：

| 类型 | 保存内容 | 示例 |
|------|----------|------|
| Memory | 事实、偏好、背景、历史决策 | 用户喜欢中文回答；项目部署在 Docker；某接口已废弃 |
| Skills | 方法、流程、风格、可复用操作步骤 | review 输出结构；政府报告写法；重构检查流程 |

Memory 在 `agents/memory.py` 里实现：

```text
保存 Memory
  -> save_memory()
  -> 写入 ~/.mawoagent/projects/<project_hash>/memory/
  -> 更新 index

召回 Memory
  -> scan_memory_headers()
  -> start_memory_prefetch()
  -> select_relevant_memories()
  -> format_memories_for_injection()
```

Memory 使用项目路径 hash 隔离，避免不同项目互相污染。

## 11. MCP 架构

MCP 用来把外部工具统一接入 Agent。

mawoagent 没有依赖 MCP SDK，而是自己实现了 stdio JSON-RPC Client。

相关模块是 `agents/mcp_client.py`。

核心对象：

| 对象 | 职责 |
|------|------|
| `McpConnection` | 管理一个 MCP Server 子进程和 JSON-RPC 通信 |
| `McpManager` | 读取配置、启动多个 Server、合并工具定义、路由调用 |

启动流程：

```text
Agent.chat() 首次执行
  -> McpManager.load_and_connect()
  -> 读取全局 / 用户 / 项目配置
  -> 启动 MCP Server
  -> initialize
  -> tools/list
  -> 包装为 mcp__server__tool
  -> 合并进 Agent.tools
```

调用流程：

```text
模型调用 mcp__server__tool
  -> Agent._execute_tool_call()
  -> McpManager.is_mcp_tool()
  -> McpManager.call_tool()
  -> JSON-RPC tools/call
```

工具调用默认最多等待 60 秒；超时后取消本地等待并返回明确错误，后续调用仍可使用该连接。服务端操作不一定会随之停止。初始化和工具发现各有 15 秒超时。

## 12. 子 Agent 架构

子 Agent 用来处理探索、规划和局部任务，减少主上下文压力。

相关模块：

| 文件 | 职责 |
|------|------|
| `agents/subagent.py` | 定义内置子 Agent，发现自定义子 Agent |
| `agents/agent.py` | 通过 `_execute_agent_tool()` 创建并运行子 Agent |

执行流程：

```text
模型调用 agent 工具
  -> Agent._execute_agent_tool()
  -> get_sub_agent_config(agent_type)
  -> 创建子 Agent
  -> 子 Agent 独立 run_once()
  -> 结果返回主 Agent
```

内置类型：

| 类型 | 工具范围 | 适用场景 |
|------|----------|----------|
| `explore` | 只读工具 | 快速定位和搜索 |
| `plan` | 只读工具 | 输出结构化计划 |
| `general` | 除 `agent` 外的工具 | 独立处理局部任务 |

## 13. Prompt 架构

Prompt 在 `agents/prompt.py` 中动态构建。

`build_system_prompt()` 会拼接：

- 基础身份和工作规则。
- 当前目录。
- Git 上下文。
- 项目规则。
- Memory 说明和索引。
- Available Skills。
- Available Sub Agents。
- 延迟工具提示。

这意味着 system prompt 不是固定文本，而是 runtime 状态的一部分。

## 14. 会话、压缩和大结果持久化

长任务会产生大量消息和工具结果，必须控制上下文体积。

相关模块：

| 文件 | 职责 |
|------|------|
| `agents/session.py` | 保存、加载、列出 session |
| `agents/agent.py` | 自动保存、恢复、压缩消息、大结果持久化 |

主要机制：

| 机制 | 说明 |
|------|------|
| `save_session()` | 保存 session |
| `load_session()` | 恢复 session |
| `_run_compression_pipeline()` | 压缩消息和工具结果 |
| `compact_context` | 主动触发上下文压缩 |
| `_persist_large_result()` | 大工具结果写文件，只把引用留在上下文中 |

这部分保证 mawoagent 不只是一轮任务工具，而是能支撑长程任务的 runtime。

## 15. 存储架构

重要路径如下：

| 数据 | 路径 | 说明 |
|------|------|------|
| 项目级 Skills | `.mawoagent/skills/<skill_name>/SKILL.md` | 当前项目专用能力 |
| 用户级 Skills | `~/.mawoagent/skills/<skill_name>/SKILL.md` | 跨项目复用能力 |
| Skill 演化审计 | `.mawoagent/skill-evolution/` | provenance、usage stats、history |
| Memory | `~/.mawoagent/projects/<project_hash>/memory/` | 项目隔离的长期记忆 |
| Session | `~/.mawoagent/sessions/` | 会话恢复数据 |
| 大工具结果 | `~/.mawoagent/tool-results/` | 大输出持久化引用 |
| Plan 文件 | `~/.mawoagent/plans/` | Plan Mode 计划 |
| MCP 配置 | `.mcp.json`、`~/.mawoagent/settings.json` | 外部工具配置 |

存储设计体现两个原则：

- 项目相关能力放项目目录。
- 用户级偏好和跨项目能力放 home 目录。

## 17. 通用 Agent Runtime

mawoagent 不是单纯的聊天 CLI，也不是只提供几个文件工具。

它的核心是一个通用 Runtime：

- 管模型协议。
- 管工具调用。
- 管权限。
- 管上下文。
- 管长期记忆。
- 管 Skills。
- 管 MCP。
- 管子 Agent。
- 管 session 和压缩。
- 管用户反馈到 Skill 的沉淀。

“通用”体现在它不依赖某个垂直场景。
“Runtime”体现在它真正控制执行边界，而不是让模型直接碰环境。
“可演化”体现在 Skills、provenance、usage stats 和评测链路。
