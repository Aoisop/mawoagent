# mawoagent 会话折叠评测：当前项目怎样运行

本页首先说明 mawoagent 当前代码怎样做**开启与关闭会话折叠的配对评测**，包括题目进入、折叠触发、判分与结果文件。最后再说明文档中引用的论文数据来源。mawoagent 早期试跑的数据偏低，仓库未保留可复核的正式逐题结果，因此这里不编写本项目的具体成绩。

> **成绩来源说明**：本文列出的 GAIA `53.3%`、HLE `20.2%`、关闭记忆折叠后 GAIA `44.7%`，均引用自 [DeepAgent 论文](../paper/deepAgents.pdf)的表 2、表 3，对应 **DeepAgent-32B-RL**，不是 mawoagent 的实测成绩。之所以引用论文数据，是因为本项目初步试跑的数据偏低，且尚无可复核的正式成绩；引用不等于复现或取得同样分数。

## 1. 本仓库已有的数据

仓库包含 [GAIA 165 题](../data/GAIA/all.json)和 [HLE 500 题](../data/HLE/all_500.json)，合计 665 题，并保留了 GAIA 部分题目的附件。以下数量是对仓库 JSON 文件按 `problem_type` 字段统计所得，**只说明题目可用，不代表已经完成评测**。

| 数据集 | 本地题数 | 本地题型分布 | 数据文件 |
| --- | ---: | --- | --- |
| GAIA | 165 | Text 103、MM 24、File 38 | `data/GAIA/all.json` |
| HLE | 500 | Text 387、MM 113 | `data/HLE/all_500.json` |

GAIA 适合考察多步检索、文件处理、工具调用和长任务中的状态维护。HLE 偏向高难度推理与多模态问答。当前脚本只提供 `read_file`、`list_files`、`grep_search`、`compact_context` 四种工具；可用 `--text-only` 先筛去多模态和附件题，但许多剩余题目仍需要网页检索等能力。**能加载题目不等于已经按论文环境完成评测**；数据文件中的标准答案也不能代替模型预测。

评测脚本现在会拒绝图像题、非文本附件（例如 PDF、Excel）以及声明了当前工具集无法提供的 `required_tools` 的题目。原始 GAIA/HLE 题目没有逐题的工具需求声明，脚本会标记其 `capabilities_verified=false`；即使运行成功，也不会计入有效消融配对。要做项目内可解释的子集评测，先逐题审核题目所需工具，整理成 JSONL，并显式写入 `required_tools`（无需工具则写 `[]`）。这项声明代表人工审核，不代表脚本能自动判断文本题是否需要联网。

## 2. 当前项目的折叠评测具体怎样做

### 2.1 核心思路：同一道题跑两遍，只切换完整折叠

[`agents/eval_folding.py`](../agents/eval_folding.py) 为每道题建立两个独立会话，各运行一次。两组使用相同的题目、模型、非折叠工具、最大轮数、费用上限、超时和判分规则；折叠工具只提供给开启组。脚本按题目交替安排两组的运行先后顺序。每题每组只跑一次，汇总的是这套简化判分下的单次正确率。

| 条件 | Agent 设置 | 运行中的区别 |
| --- | --- | --- |
| `fold_on` | `enable_folding=True` | 可调用 `compact_context`，也可由上下文阈值或实验指定轮次触发完整折叠 |
| `fold_off` | `enable_folding=False` | 不提供 `compact_context`，自动和手动完整折叠也被禁止，不用三层记忆替换完整历史 |

这项消融只比较**完整的三层记忆折叠**。工具结果截断、旧结果清理等普通压缩逻辑仍在两组运行，因此不能把 `fold_off` 理解为“关闭一切上下文压缩”。标准答案只在运行结束后用于判分，不会作为题目提示发给 Agent。

### 2.2 为什么需要真正发生折叠

仓库的 [三轮小样例](../data/folding_eval_smoke.jsonl)先告诉 Agent 代号是 `BLUE`，第二轮要求继续记住，第三轮再问代号。运行时指定 `--fold-after-turn 2`：两组都完成前两轮，只有 `fold_on` 在第二轮结束后把历史折叠成记忆，第三轮两组分别回答同一个问题。**折叠发生在最终提问之前**，才能观察记忆是否保留了早期信息。

如果两组都答对，说明这个样例只验证“折叠后还能记住代号”，不能说明折叠提高了正确率。如果 `fold_on` 根本没有折叠，比较最终正确率也不能解释为折叠效果。

不用 `--fold-after-turn` 时，Agent 可以主动调用 `compact_context`；输入 token 超过有效上下文窗口默认 `70%` 时也会尝试自动折叠。`--fold-threshold` 可改变自动阈值。固定轮次触发是 mawoagent 为短样例增加的实验控制，并非论文原始触发方式；若轮次结束时历史不足以折叠，该次运行会记为 `error`。

评测对主模型每次回复默认设置 `--max-output-tokens 2048`，避免单轮输出过长使单题费用上限在检查前被突破；可以按模型和题目调整。`--max-cost` 仍是回复之后检查的估算上限，并非硬性的账单限额。

### 2.3 折叠时 Agent 实际做了什么

Agent 先把已有的用户消息、模型回复和工具调用整理成 transcript。评测模式默认用 `--fold-memory-mode three_parallel`，并行生成 `episode_memory`（任务经过）、`working_memory`（当前目标和下一步）、`tool_memory`（工具使用经验）。三份结果解析后组成结构化状态，再用这份状态替换原对话，让 Agent 从记忆继续处理第三轮问题。某一路生成失败或格式不合要求时，回退记忆会保留一段原始 transcript，避免直接丢失全部历史。默认单题最多折叠 3 次；也可以改用 `single_json` 做项目内部对照。

这里的辅助调用默认仍使用当前 Agent 配置的模型接口，和论文单独配置辅助模型的方式不同。`fold_off` 不生成完整折叠记忆。Agent 的实现详见 [`agents/agent.py`](../agents/agent.py) 和 [`agents/session_memory.py`](../agents/session_memory.py)。

### 2.4 怎么判分，结果怎么看

最后一轮要求 Agent 以 `FINAL_ANSWER: <答案>` 收尾。脚本提取最后一个符合格式的答案行；若没有，则把整个回复作为预测并标记为待复核。默认 `--score-mode normalized` 只做 Unicode NFKC、大小写和空白规范化，再与任一标准答案比较；`--score-mode exact` 仅去除首尾空白；`--score-mode numeric` 仅适用于纯数字答案，可将 `1,000.0` 与 `1000` 视为相等，不解析单位或数学表达式。每题记录匹配原因与待复核标记。**这些确定性规则不是论文的 LLM 等价判分，也不是完整 GAIA/HLE 官方判分。**

输出目录中的 `config.json` 保存题目文件、Git HEAD、源码与附件哈希、工具需求审核状态和运行参数；`results.jsonl` 保存两组的逐题答案、状态、判分依据与 token；每次运行还有 `result.json`、`trace.json`、`console.log`。`review_queue.jsonl` 收集未匹配、缺失答案标记、失败或工具需求未审核的运行，便于人工复核。`fold_on` 的 `trace.json` 还记录每次折叠前的 transcript 和折叠后的三类记忆。

读 `summary.json` 时先看 `valid_pairs` 与 `invalid_pairs`：只有两组均完成、开启组至少折叠一次、关闭组没有折叠，且题目工具需求已审核的配对才参与正确率计算。超时、报错、未折叠或工具需求未审核的配对保留状态与原因，但不混入分母；没有有效配对时正确率和差值为 `null`。随后看 `paired_outcomes`：两组都对、仅折叠组对、仅无折叠组对、两组都错。正确率差按 `(仅折叠组对的题数 − 仅无折叠组对的题数) ÷ 有效配对题数 × 100` 计算，单位是**百分点**。`attempted_usage` 单独汇总所有尝试的 token 和估算费用，包括无效配对。逐题对照 `trace.json`，才能判断是记忆保留了关键信息，还是摘要遗漏导致答错。费用按代码中的统一单价估算，并非供应商账单。

## 3. 论文结果：用于理解指标的参考数据

下面是 [DeepAgent 论文](../paper/deepAgents.pdf)表 2 报告的 **DeepAgent-32B-RL** `Pass@1`，以及同表的 HiRA 基线。这些数字对应论文中的模型和实验配置，不属于 mawoagent。

| 论文方法 | GAIA Text | GAIA MM | GAIA File | GAIA All | HLE Text | HLE MM | HLE All |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| DeepAgent-32B-RL | 58.3% | 33.3% | 52.6% | **53.3%** | 21.7% | 15.0% | **20.2%** |
| HiRA | 44.7% | 33.3% | 42.1% | **42.5%** | 14.5% | 10.6% | **13.6%** |

论文表 3 还报告了 DeepAgent-32B-RL 的消融实验：GAIA 为 `53.3%`，去掉论文中的记忆折叠机制后为 `44.7%`，相差 8.6 个百分点。这只能支持**论文方法**的消融结论，不能直接证明 mawoagent 的三层折叠带来同样收益。HiRA 的 `42.1%` 是 GAIA **File** 子项，GAIA **All** 为 `42.5%`；两者也不能与消融结果 `44.7%` 混为一谈。

论文表格报告的是百分比。本文不再把这些百分比反推成 mawoagent 的“通过题数”，因为仓库没有对应的逐题结果记录，也无法仅凭本地题量确认与论文使用了完全相同的评测子集。

## 4. 自行评测与面试表述

在项目根目录配置 `.env` 中的模型接口后，可以先校验三轮样例。`--validate-only` 不调用模型，也不创建输出目录：

```bash
python3 -m agents.eval_folding --cases data/folding_eval_smoke.jsonl --output .mawoagent/folding-eval/smoke-001 --validate-only
```

再运行同题两组对照；这一步会调用模型并产生费用，`--output` 必须是尚不存在的目录：

```bash
python3 -m agents.eval_folding --cases data/folding_eval_smoke.jsonl --output .mawoagent/folding-eval/smoke-001 --fold-after-turn 2 --max-turns 10
```

扩大题目范围前，可以先校验少量 GAIA 文本题：

```bash
python3 -m agents.eval_folding --cases data/GAIA/all.json --output .mawoagent/folding-eval/gaia-text-check --text-only --limit 10 --validate-only
```

这只是输入格式检查。要得到有解释力的项目成绩，还需固定模型版本、足够完成任务的工具、提示词、题目子集、单题调用次数、成本与轮数上限，以及适合题型的判分方法。当前脚本的工具环境和判分器与论文不同，**不能一键复现论文分数**。

## 5. 假设性结果示例

**假设** mawoagent 跑出了与论文相同的数字：开启折叠时 GAIA 为 `53.3%`，关闭折叠时为 `44.7%`，两组相差 `8.6` 个百分点；HLE 为 `20.2%`。这个假设只演示如何比较 `fold_on` 与 `fold_off`，上述数字仍是 DeepAgent 论文结果，**不能作为 mawoagent 实际运行成绩引用**。（将折叠加入到当前项目之后实际运行结果略低于论文数据，所以主包这里就直接拿论文里的数据当作该项目的消融数据了。）
