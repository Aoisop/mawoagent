# mawoagent 从 0 到 1 学习了解项目

**如果我们想理解、控制并持续演化一个通用 Agent，它的底层运行时应该长什么样？**

mawoagent 参考了 Claude Code 一类产品的底层机制，但它不是一个垂直 Coding Agent。
它的定位是一个更通用、更容易学习、更容易二次开发的 Agent Runtime。

## 1. 项目定位

mawoagent 的核心不是“聊天”，而是“运行时”。
模型负责推理和提出工具调用意图，Runtime 负责权限、工具执行、上下文管理、会话恢复、Skills 自进化和外部扩展。

它想验证的是一件事：

- 一个通用 Agent 能不能被清楚地组织成一个可控的 loop。
- 长程任务状态能不能被结构化保存和恢复。
- 用户反馈能不能沉淀成长期能力。
- 新能力能不能被审计、演化和回放。
- 外部工具、子 Agent、Skills、Memory 能不能统一挂到同一个 runtime 里。

所以 mawoagent 更像一个通用 Agent 底座，而不是某个单点场景的产品。

## 2. 为什么还要做它

今天已经有很多强 Agent 和框架。
mawoagent 不是为了重复做一个“更强聊天工具”，而是为了把下面这些底层机制讲清楚、控清楚、改清楚：

- agent loop
- tool call
- 权限边界
- 上下文压缩
- session 恢复
- 子 Agent
- Skills
- 长程任务状态
- 自进化

这些能力不只属于 Coding Agent。
写作、研究、信息整理、文档生成、流程执行、资料分析、个人助理，都需要类似的底层结构。

mawoagent 的价值在于：它把这些机制收进一个简单、透明、可学习的 Python runtime 里。

## 3. 代码在解决什么问题

mawoagent 的运行方式不是：

```text
用户输入 -> 模型回复
```

而是：

```text
用户输入
  -> 构建 system prompt / Skills / Memory / 工具上下文
  -> 调用模型
  -> 解析文本或 tool call
  -> Runtime 判断是否允许执行
  -> 执行工具、Skill、MCP 或子 Agent
  -> 把结果回写给模型
  -> 必要时压缩上下文
  -> 保存 session
  -> 记录使用情况并触发自进化
```

模型只负责“想做什么”，Runtime 负责“能不能做、怎么做、做完怎么记住”。

## 4. 核心链路

主入口在 `agents/main.py`，真正的运行时在 `agents/agent.py`。

一次请求大致会经过：

1. 读取 `.env` 和命令行参数。
2. 决定权限模式和模型接口。
3. 创建 `Agent`。
4. 组装 system prompt。
5. 检索相关 Skills。
6. 预取 Memory。
7. 必要时连接 MCP。
8. 调用模型。
9. 处理 tool call。
10. 执行内置工具、Skill、子 Agent 或 MCP 工具。
11. 回写 tool result。
12. 继续下一轮直到结束。
13. 保存 session。
14. 触发 Skill 使用统计和在线自进化。

## 6. 它和 Coding Agent 的区别

mawoagent 参考了 Coding Agent 的工程骨架，但它不把自己限定在代码场景里。

区别可以这么理解：

- Coding Agent 会围绕软件工程流程做垂直优化。
- mawoagent 更强调通用 runtime、可读性和可改造性。

也就是说，它不是“再做一个更强的代码助手”，而是做一个能被拿去改造成各种通用 Agent 的底座。

## 7. Skills

通用 Agent 面对的任务很散。
如果每次都只靠当前上下文，用户就得反复说明同样的偏好、方法和工作流。

Skills 解决的是“长期可复用能力”问题。

它沉淀的不是一次性内容，而是：

- 输出规范
- 工作流
- 判断标准
- 任务触发条件
- 用户偏好
- 领域方法

代码里，Skills 通过目录型 `SKILL.md` 存储，支持：

- 检索
- 手动调用
- 模型调用
- fork 执行
- 创建
- 演化

## 8. 自进化

mawoagent 的 Skills 自进化不是“让模型随便改自己”。

它的做法更像一个可审计的闭环：

```text
本轮任务 + assistant 输出
  -> 保存 pending window
下一轮用户反馈
  -> 合并证据
  -> 抽取候选 Skill
  -> 检索相似 Skill
  -> 决策 add / merge / discard
  -> 写入或演化 SKILL.md
  -> 记录 provenance / history / usage
```

这么做是为了避免：

- 把一次性内容误写成长期规则
- 把隐私和临时参数沉淀进能力
- 把幻觉当成经验
- 让技能越积越多但不可控

## 9.长程任务

通用 Agent 真正难的地方，往往不是回答一个问题，而是连续推进一个任务。

长程任务里会出现：

- 上下文不断变长
- 工具结果不断变多
- 中间结论需要保留
- 当前目标容易被噪声淹没
- 会话中断后需要继续

mawoagent 通过这些机制处理它：

- session 保存
- session folding
- compact_context
- Memory
- Skills
- 子 Agent

它的目标不是记住所有字，而是知道“现在该继续什么”。

## 10. 权限边界

只要引入工具，模型就不再只是文本生成器。
它可能会读文件、写文件、执行命令、调用外部服务。

所以 mawoagent 把模型和执行环境分开：

- 模型提出意图
- Runtime 决定是否允许
- 工具真正执行

这就是 `agents/tools.py` 里的权限系统、危险命令检查、Plan Mode 和编辑前读取校验的意义。

## 11. 通用扩展方式

mawoagent 的扩展不是写死在一个大框架里，而是通过几个清楚的入口接入：

- 新工具：加到 `tools.py`
- 新 Skill：加到 `.mawoagent/skills/`
- 新子 Agent：加到 `.mawoagent/agents/`
- 新外部工具：接 MCP
- 新长期事实：写 Memory

这些扩展最后都会被同一个 Agent Runtime 编排。

## 12. 介绍

如果要用一句话讲：

**mawoagent 是一个通用 Agent Runtime，用来学习、控制和演化一个可运行的 agent loop。**

如果要稍微展开一点：

mawoagent 参考了 Claude Code 一类产品的底层架构，但它不是一个垂直 Coding Agent。
它把模型、工具、权限、Memory、Skills、自进化、MCP 和子 Agent 收进一个透明的本地 runtime，方便学习和二次开发。
